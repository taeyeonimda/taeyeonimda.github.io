Salesforce 개발자 문서의 AI 친화적 변화: llms.txt와 Markdown 파이프라인 활용법

최근 Cursor, Claude, ChatGPT 등 AI 도구를 개발 워크플로우에 적극 도입하는 분위기 속에서 가장 자주 겪는 문제 중 하나는 “AI에게 최신 공식 문서 문맥(Context)을 정확하고 효율적으로 전달하는 방법”입니다.

웹 브라우저로 접속하는 일반적인 기술 문서는 사람이 읽기에는 최적화되어 있지만, LLM(대형 언어 모델)에 입력하기에는 심각한 오버헤드가 발생합니다. 상단/하단 네비게이션 바, CSS 스타일링, 복잡한 DOM 구조, 클라이언트 사이드 렌더링(CSR) 쉘 등은 불필요한 토큰(Token)을 대량 소비시킬 뿐만 아니라, AI가 정작 필요한 Apex 클래스 명세나 LWC 컴포넌트 샘플 코드를 오독하게 만드는 원인이 됩니다.

Salesforce는 이러한 문제를 해결하기 위해 공식 개발자 문서 아키텍처를 개편했습니다. 이에 대한 상세한 배경과 기능은 공식 아티클 Bring Salesforce Developer Docs into Your AI Tools에서 확인할 수 있습니다.

본 포스트에서는 Salesforce가 도입한 AI 친화적 문서 생태계의 핵심 구조를 살펴보고, 이를 현업 프로젝트 워크플로우(IDE 및 AI 에이전트 연동)에 즉시 적용하는 실무 방법을 정리합니다.

1. 기존 웹 문서 방식의 한계와 새로운 접근법

과거 개발자 문서 웹페이지를 AI 도구에 전달할 때 발생했던 대표적인 문제는 다음과 같습니다.

  1. 토큰 낭비 및 정보 오염: 웹페이지의 전체 HTML을 긁어오면 본문보다 불필요한 마크업(DOM 메타데이터, 레이아웃 태그 등)이 더 큰 비중을 차지합니다.
  2. 복사-붙여넣기 시 서식 깨짐: 웹 화면의 텍스트를 드래그해 붙여넣으면 마크다운 헤더(#), 리스트 구조, 코드 블록( `` `) 구분이 상실되어 AI가 코드와 일반 설명을 혼동합니다.
  3. 단편적 정보 수집의 한계: 수만 페이지에 달하는 Salesforce 제품 문서 특성상, 특정 기능의 가이드 URL 하나만 주면 연관된 데이터 모델이나 API 명세를 AI 스스로 탐색하기 어렵습니다.

Salesforce는 개발자 문서 플랫폼(SFDocs)을 개편하여 웹페이지 빌드 시 HTML과 동시에 동일한 경로의 순수 마크다운(.md) 파일 및 표준 인덱스 파일(llms.txt)을 생성하도록 구조를 전환했습니다.

2. 핵심 변경점 3가지 및 실무 활용

Salesforce 개발자 문서 상단에 새로 추가된 툴바를 이용하면 다음 기능들을 즉시 활용할 수 있습니다.

① Clean Markdown 즉시 추출 (Copy / View as Markdown)

문서 상단의 Copy as Markdown 또는 View as Markdown을 클릭하면 HTML 마크업이 제거되고 정형화된 마크다운 텍스트를 얻을 수 있습니다.

  • 코드 블록에는 정확한 언어 지정(예: javascript, apex, xml)이 유지되므로 AI가 서식을 완벽히 인지합니다.
  • 토큰 소비량이 기존 웹페이지 긁어오기 대비 최대 60~80% 감소합니다.

② open standard: llms.txt 지원

llms.txt는 웹사이트의 핵심 문서를 AI 에이전트가 빠르게 파악할 수 있도록 돕는 오픈 표준 목차 파일입니다. Salesforce 메인 llms.txt 파일은 Agentforce부터 LWC, Apex, Pub/Sub API에 이르기까지 40개 이상의 제품군 마크다운 경로를 체계적으로 인덱싱하고 있습니다.

llms.txt를 에이전트에 제공하면 에이전트가 외부 웹 검색(Google/Bing)에 의존하여 잘못된 구버전 정보를 가져오는 환각(Hallucination) 현상을 대폭 줄일 수 있습니다.

③ AI 어시스턴트 즉시 호출 (Open in ChatGPT / Claude / Perplexity)

More actions 메뉴를 이용하면 현재 보고 있는 문서의 URL과 메인 llms.txt 경로가 사전 정의된 프롬프트와 함께 선택한 AI 툴의 새 탭으로 자동 전송됩니다.

3. 현업 프로젝트 실무 적용 시나리오

개발 현장에서 이 기능을 활용해 코드 생산성을 극대화하는 실전 패턴 2가지를 소개합니다.

시나리오 A: Cursor / VS Code IDE 내 규칙 파일(.cursorrules) 연동

# LWC 코딩 가이드라인

개발 시 아래 Salesforce 공식 문서 및 인덱스를 참조하여 최신 구문을 사용하세요.

- **전체 문서 지침 (Index)**: https://developer.salesforce.com/docs/llms.txt
- **LWC Context 참조**: https://developer.salesforce.com/docs/platform/lwc/guide/use-context.md

## 구현 규칙
1. `@salesforce/schema` 참조 시 대소문자를 엄격히 준수할 것.
2. Wire 서비스 사용 시 오류 처리는 `reduceErrors` 헬퍼 모듈 형태를 권장함.
3. DOM 조작은 절대로 직접 하지 말고 LWC 데이터 바인딩을 활용할 것.

시나리오 B: Python을 이용한 로컬 RAG 시스템 / AI Agent 문서 자동 수집

자체 AI 에이전트를 구축하거나 내부 지식 베이스를 갱신할 때 llms.txt 파싱을 통해 자동으로 최신 마크다운 문서를 다운로드하는 간단한 파이프라인 예시입니다.

import requests
import re
import os

# Salesforce LWC 전용 llms.txt 경로
LLMS_TXT_URL = "https://developer.salesforce.com/docs/platform/lwc/llms.txt"
OUTPUT_DIR = "./sf_docs_lwc"

def download_markdown_docs():
    os.makedirs(OUTPUT_DIR, exist_ok=True)
    
    # 1. llms.txt 가져오기
    response = requests.get(LLMS_TXT_URL)
    if response.status_code != 200:
        print("llms.txt 로드 실패")
        return

    # 2. 마크다운(.md) 링크 추출
    lines = response.text.splitlines()
    md_urls = [line.strip() for line in lines if line.strip().endswith('.md')]

    print(f"총 {len(md_urls)}개의 마크다운 문서 수집 시작...")

    # 3. 문서 다운로드
    for url in md_urls:
        file_name = url.split('/')[-1]
        save_path = os.path.join(OUTPUT_DIR, file_name)
        
        doc_resp = requests.get(url)
        if doc_resp.status_code == 200:
            with open(save_path, 'w', encoding='utf-8') as f:
                f.write(doc_resp.text)
            print(f"저장 완료: {file_name}")

if __name__ == "__main__":
    download_markdown_docs()

4. 실무 적용 시 주의사항 (Gotcha) 및 한계점

이 기능을 현업에 도입할 때 반드시 인지해야 할 3가지 한계점이 있습니다.

1. 영문(English) 문서 전용 지원
현재 마크다운 변환 및 llms.txt 제공 기능은 영문 공식 문서(developer.salesforce.com/docs)에서만 제공됩니다. 한국어 변환 페이지에는 해당 상단 액션 툴바가 출력되지 않으므로, AI 도구에 맥락을 제공할 때는 영문 URL 및 마크다운을 사용해야 최상의 결과를 얻을 수 있습니다.

2. OpenAPI 기반 API Reference 페이지 미지원
일부 REST API / Tooling API 명세서 등 OpenAPI 스펙 파일에서 자동 생성되는 문서 페이지는 마크다운 소스가 별도로 존재하지 않아 툴바 버튼이 비활성화되어 있습니다.

3. AI 도구의 Web Browsing 권한 필요
Open in ChatGPT 등의 기능은 본문 전체를 텍스트로 전달하는 것이 아니라 마크다운 URL을 프롬프트로 전달합니다. 따라서 사용하는 AI 솔루션의 외부 웹 접속(Web Search/Browsing) 기능이 활성화되어 있어야 에이전트가 해당 마크다운을 정상적으로 읽어옵니다.

5. 마무리 및 실무 체크리스트

Salesforce 문서의 이러한 변화는 단순한 편의기능 추가를 넘어, 개발자가 사용하는 AI 도구에 최적화된 Context 데이터를 제공하는 표준 패러다임을 보여줍니다.

현업 개발 팀이라면 다음 체크리스트를 바탕으로 AI 개발 환경을 재정비해 보길 권장합니다.

  • 프로젝트 내 자주 참조하는 Salesforce 가이드의 .md URL 확보하기
  • Cursor / Roo Code 등 IDE 규칙 파일에 Salesforce llms.txt 주소 등록하기
  • AI 프롬프트 작성 시 단순 텍스트 복사 대신 Copy as Markdown 활용하기
  • 한국어 번역 문서 대신 영문 마크다운 원본을 AI에게 전달하여 환각(Hallucination) 방지하기
